# Netflix FAM profile interaction review — working notes

## Initial profile-selection surface

The entry screen presents a single focused decision: **“Who’s watching?”**. It uses a centered card row on a dark, uncluttered backdrop, with large square avatars, profile labels, a visual lock indicator on the locked profile, an add-profile tile, and a separate **Manage Profiles** action. The selected unlocked `fam` profile is the permitted reference surface. The locked `ron` profile will not be opened.

## FAM home surface

After choosing `fam`, the desktop experience uses a compact sticky top navigation with Home, Shows, Movies, Games, New & Popular, My List, and Browse by Languages. Utility controls include search, notifications, a kids shortcut, and a profile menu. The landing space is led by a full-width cinematic hero with title branding, concise metadata, synopsis, primary Play and secondary More Info actions, and a small promotional/status treatment.

Below the hero, discovery is structured as horizontally scrollable editorial rails. Observed rail patterns include personalized recommendations, theme or genre collections, My List, and Continue Watching. Cards are content-first and must support hover/focus actions rather than forcing immediate playback. The Kryv implementation should adapt the hierarchy and interaction grammar rather than copy Netflix assets, wording, or branding.

## Scope to inspect next

The review will cover browse navigation, rail movement and hover states, title detail, search, My List, profile menu and management, account/privacy links, playback-entry behavior, responsive/mobile navigation, and the contrast between desktop and narrow-screen interaction patterns.

## Shows-category findings

The Shows section preserves the global navigation but changes the hero and introduces an immediately visible **Genres** control next to the category heading. The structure is not a flat catalog: it starts with a featured title and editorial context, then moves into several named recommendation rails. The hierarchy makes switching from a broad category to a narrower taste path inexpensive.

Title cards remain compact in the rail at rest and are individually focusable. The interaction model should be implemented accessibly in Kryv with keyboard focus and touch-safe explicit actions, not hover alone. Kryv should use a focused-card treatment that can reveal quick play, details, add/remove list, and maturity/context cues without making the layout unstable.

## Design requirements derived so far

1. Cinema needs a persistent, responsive navigation hierarchy, a featured hero, editorial rails, category filtering, personal list, and continuation row.
2. Profile selection must remain a distinct entry state; management and locking must be owner-controlled and not be conflated with everyday viewing.
3. Desktop hover behavior must have an equivalent focus and tap affordance for keyboard and mobile users.
4. Hero actions should support an explicit viewing-entry choice and a detailed title view; the implementation must not automatically start media during browsing.

## Title-detail findings

Selecting **More Info** opens an immersive centered overlay above a dimmed browse page rather than forcing a route transition. The overlay combines a backdrop, title treatment, primary play entry, My List control, rating/feedback affordance, audio toggle, close control, metadata, maturity context, synopsis, cast, genre, and tone tags. Series add a season picker and a vertically legible episode list with episode number, thumbnail, title, duration, and short summary.

The transferable pattern for Kryv is a **non-destructive title-detail layer**: browsing context stays visible behind the detail view, the close affordance is unambiguous, and title decisions can be made without starting playback. Kryv should add detail overlay or page support with title metadata, public credits, content context, watch-entry action, list control, and season/episode navigation where applicable. Any profile lock must be enforced before profile-specific playback state or age-restricted content becomes visible.

## Playback-entry finding

A title or episode play action transitions into a full-screen, low-distraction player route. At the loading state, the essential visible recovery/navigation control is **Back to Browse**. This supports a Kryv design in which media viewing has a clearly separated, immersive entry surface and a reliable escape path to the prior browsing context. The implementation should preserve active profile context and only record progress after a legitimate viewing start.

## Additional title affordances

The title detail offers an explicit list action, a feedback-style action, audio control, close control, age/maturity label, and linked credits/genres/tone terms. The browser return flow restores the browse context. For Kryv, the equivalent should persist the selected profile and browsing path, keep the close/back behavior predictable, and ensure profile-scoped controls (watchlist and progress) are never shared across profiles.

## Search findings

Search expands from the utility icon into a compact top-bar field with the broad prompt **“Titles, people, genres.”** A submitted representative query produces a dense visual result grid that mixes direct title matches, collection matches, related material, and a visible **More to explore** refinement row. The results retain the global navigation and profile context. Kryv Cinema should implement debounced, keyboard-accessible search with clear input reset, direct matches, related people/genres where available, an empty state, and responsive card density.

## Profile-management and privacy findings

The profile-management section separates **account-level navigation** (overview, membership, security, devices, profiles) from **profile-level preferences**. The profile list identifies the currently active viewer and provides an explicit profile-management route. The unlocked FAM profile settings organize controls into clear, independent rows: profile identity/contact information, **Profile Lock** with a PIN requirement, languages, parental controls, subtitle appearance, playback settings, notifications, viewing activity, privacy/data settings, and profile deletion.

Kryv should mirror the separation of concerns rather than combine all account settings in one form. The minimum profile feature should include a profile picker, owner-controlled profile creation/edit/delete, a profile-scoped PIN lock, a recovery/reset procedure requiring account-owner reauthentication, profile preference storage, profile-specific list/progress history, privacy-data export/deletion pathway, and clear age/content guard boundaries. Lock configuration and reset must be audited, rate-limited, hashed at rest, and must invalidate profile-unlock grants after reset.

## Movies-category findings

The Movies surface follows the same structural grammar as Shows—category heading, visible genre control, featured hero, and named discovery rails—but changes the editorial signals and catalog context. Observed examples include topical rows and an explicit **Top 10** rail, while the hero can display time-sensitive availability messaging. Kryv Cinema should make the rail system reusable across content types, permit category-specific editorial labels and availability notices, and keep ranking badges/data distinct from marketing copy.

## New & Popular and personal-list findings

The New & Popular surface is a catalog-first landing page rather than a hero-led page. It exposes separate rails for new arrivals, ranked Top 10 titles, and an upcoming-release row. Ranking is visually encoded with oversized ordinal numerals layered behind posters; item badges communicate signals such as newly added, upcoming, or new season. Kryv can adopt a data-driven editorial badge system and a transparent ranking model without copying any Netflix artwork or labels.

The My List screen is intentionally sparse: a simple heading, stable global navigation, and a single personal grid. It confirms that a saved list is a **profile-scoped** data set, not an account-global one. Kryv should provide the same clarity, including an empty state that explains how to save a title, predictable add/remove affordances in title details, and independent lists for every selected profile.

## Language-discovery findings

Language discovery is presented as an explicit catalog mode, with separate criteria for original language, dubbing, and subtitles plus a language selector. Results are rendered as a regular title grid with the chosen filter context held at the top. For Kryv, audio/subtitle availability should be part of title metadata and query filters, while profile preferences should set defaults without silently modifying the catalog filter. The interface must make available-language labels, captions, and audio-description support legible on desktop, mobile, and future TV focus navigation.

## Extended Original-title findings

The Netflix Original title detail expands beyond basic metadata into a complete content hub: title status and maturity context, a season and episode navigator, collection/franchise grouping, multiple related-content sections, trailers and companion material, and an About section with creator/cast/genre/tone/maturity detail. The primary viewing affordance can become a contextual **Next Episode** action when progress exists. Kryv should model these as original content metadata and relationship types—series, season, episode, collection, related titles, trailers, people, genre, maturity, availability, and resume point—rather than storing only a single video URL.

The requested launch treatment should be an original Kryv design: a short optional branded pre-roll on a neutral dark/bright canvas, clear skip control, reduced-motion respect, muted autoplay default, and an immediate, accessible route into the actual player. Browser automation does not provide reliable audio capture, so implementation must use a newly created Kryv-owned mark and optional sound rather than attempting to reproduce a third-party sonic identity.

## Original playback-entry observation

The observed player entry uses a dark full-screen loading canvas with a minimal recovery control before media becomes available. Returning from playback restores a full title-detail overlay with a visual backdrop, a large contextual resume/next action, list and feedback controls, audio toggle, maturity labels, rich metadata, and a season selector. These observations reinforce an original Kryv launch system: a short optional branded transition, no reliance on third-party media or sound, direct skip/back controls, loading and error states, and immediate return to the selected title context.

## Expanded home-screen audit

The home experience applies the same hero layout to varied content types and exposes editorial badges such as Top 10 tenure directly in the recommendation flow. Top navigation and primary hero actions participate in a keyboard-focus sequence. Kryv must deliver a visible focus indicator, logical tab order, skip-to-content link, fully labelled controls, reduced-motion support, and touch-safe versions of all hover affordances. These are baseline requirements for web, mobile-web, and later TV remote navigation.

## Rail-card density and loading design

Lower home rails show a stable visual rhythm: large compact landscape cards, one editorial heading per rail, lightweight per-card badges, and a single end-of-row control to reveal more titles. The rails intentionally expose only a small number of items in the first viewport while preserving continuation through horizontal progression. Kryv should render fixed-ratio poster/backdrop placeholders, reserve image layout space to prevent content shift, use responsive derivatives (`srcset`/sizes or CDN transforms), lazy-load below-the-fold art, prioritize the hero and first visible rail, and avoid preloading remote previews until an explicit hover/focus delay or user action.

## Secondary-mode and release-experiment findings

Netflix introduces Games as a first-class navigation mode while preserving the global top-bar model. The mode begins with an explicit beta disclosure, then uses the same featured-item plus rails structure as video discovery. Game cards include compact capability metadata such as category, player count, and expected session duration. The transferable pattern is not the games catalog itself; it is **progressive capability release**: announce beta state clearly, set expectations, expose a scoped feedback/exit path, and retain a stable surrounding shell. Kryv can use this pattern for experimental Cinema, Watch, or Live capabilities without confusing existing users.

## Public markup and resource-delivery observation

The observed Netflix Games markup delivers catalog artwork from a dedicated media domain in modern image formats and preloads only core font resources. The page contains many art references but does not expose an implementation pattern Kryv should copy directly. Kryv’s own equivalent should use an owned image CDN or object storage with cache versioning, immutable image URLs, generated responsive derivatives, modern AVIF/WebP where supported, explicit width/height or aspect-ratio reservation, `loading="lazy"` for below-fold art, `decoding="async"`, high-priority only for the current hero/first visible visual, and a separate image quality budget for mobile, desktop, and future TV clients.
